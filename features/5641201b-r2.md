## 2. Root cause & decisions

# Decision — 5641201b follow-up: guard BenchmarkCard $ render

ROOT_CAUSE: In the merged savings-dashboard (9fe1364b), the additive-$ guard was applied
to TotalsCard/LifetimeStrip/ShareCard but NOT to BenchmarkCard. BenchmarkCard called
`pricingNote(b.pricing)` and `money(b.saved_usd)` directly, so a 200 `/api/savings/benchmark`
whose committed result JSON is missing the `pricing`/`saved_usd` fields (a malformed file or
a partial deploy) throws `p.input_per_mtok.toFixed` on undefined during render and blanks the
entire private `/receipt` page. `fetchBenchmark`'s `.catch` only handles fetch/HTTP errors,
not a well-formed 200 with a shape mismatch. Flagged as the single major by review-5641201b
(approved-with-findings, non-blocking).

## Fix
- Extracted the guard into one shared, tested pure predicate:
  `hasDollarFigure({saved_usd, pricing})` in `format.ts` — true only when BOTH a finite
  `saved_usd` and a `pricing` block are present.
- Applied it at all FOUR $-render sites (TotalsCard, LifetimeStrip, ShareCard, BenchmarkCard)
  so the guard can no longer drift between them (the drift is exactly what caused this bug).
- BenchmarkCard now renders the token figure (`savings_pct`, baseline→trovex, spread) alone
  when the $ half is absent — never a fabricated `$0.00`, never a crash.

## Rejected alternatives
- Widen `fetchBenchmark`'s catch to swallow shape errors → rejected: a malformed benchmark
  should still render its valid token fields, not be dropped whole; the guard at the render
  site is the precise fix.
- Leave the four inline `Number.isFinite(...) && pricing != null` guards duplicated →
  rejected: the duplication is what let BenchmarkCard miss the guard; a shared tested
  predicate prevents recurrence and gives the invariant a regression test (node env can't
  render the JSX, so the predicate is the testable seam).
