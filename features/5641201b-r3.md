# Decision — 5641201b-r2 follow-up: guard against partial pricing object

ROOT_CAUSE: The r2 guard `hasDollarFigure` checked `pricing != null` but not that
`pricing.input_per_mtok` (the field `pricingNote` dereferences) is finite. A 200 payload
with a present-but-partial pricing object (`{}` from malformed committed JSON) passed the
guard, then `pricingNote` ran `undefined.toFixed()` and blanked the whole /receipt page —
the same malformed-JSON crash class the guard was added to stop. Flagged as the single
major by review-5641201b-r2 (approved-with-findings, non-blocking).

## Fix
- `hasDollarFigure` now returns true only when BOTH `saved_usd` and
  `pricing.input_per_mtok` are finite (`Number.isFinite(x.pricing?.input_per_mtok)`),
  guarding the exact field the downstream `pricingNote` reads rather than just the block.
- Applies at all four $-render sites automatically (they all call the shared predicate).
- test: `{}` and `{input_per_mtok: NaN}` pricing objects now fail the guard.

## Rejected alternatives
- Make pricingNote itself defensive (return '' on a bad block) → rejected: the render-site
  guard is the single chokepoint; keeping the predicate the sole source of truth avoids a
  second, drift-prone guard and keeps pricingNote a pure formatter.
