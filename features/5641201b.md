# Decision — 5641201b: $-priced savings dashboard + benchmark + shareable receipt

ROOT_CAUSE: trovex's core moat is "measured token savings," but the web surface only
proved it as an ESTIMATE (the client-side `/savings` calculator) and a token-only
private dashboard (`/receipt`). There was no $-priced figure, no reproducible-benchmark
surface, and no shareable artifact — so the moat read as a claim, not proof, and the
study's #1 gap (awareness, doc 37fa8519) had no dark-social atom to travel on.

## What this change does
Renders trovex-backend's new $-ledger + reproducible-benchmark (task cfa5c328) on the
existing private `/receipt` dashboard, and adds the shareable receipt artifact:
- $-priced savings paired with the existing token figure + pricing provenance.
- A reproducible-benchmark card (headline %, baseline→trovex, median/pooled spread,
  methodology link, deterministic badge).
- A share section: an aggregate-only, honesty-stamped PNG (client canvas, no infra) +
  a copy-line. Closes the awareness loop without exposing repo/paths/queries.

## Contract (settled with trovex-backend on the relay, msgs be3960f5 / a0da3bcd)
ADDITIVE, no existing keys change:
- `saved_usd`, `saved_usd_at_precision` on totals + agent + session rows.
- one top-level `pricing:{model,input_per_mtok,source}` block.
- new `GET /api/savings/benchmark` → {corpus, queries, savings_pct, baseline_tokens,
  trovex_tokens, saved_usd, median_ratio, pooled_ratio, pricing, methodology_url,
  ran_at, deterministic}.
Split: backend exposes numbers only; frontend renders the public React receipt + client
PNG. No PNG/OG endpoint from backend (avoids double-build).

## Key decisions
- The $ figure rides the SAME verified/raw tier as the tokens (via `resolveHeadline`),
  so tokens and dollars can never disagree on a shared card.
- Honesty preserved end-to-end: `$-at-precision` falls back to the raw $ floor and never
  inflates; `money()` under-claims (no fabricated number); the share card is stamped
  `routing verified` / `raw estimate`.
- The $ layer is guarded as strictly ADDITIVE: a server deployed before the $ fields land
  renders tokens-only cleanly rather than a fake `$0.00` (handles deploy-ordering between
  the two in-flight tasks).
- `/receipt` stays private-by-construction (never indexed); the shareable artifact is a
  PNG the user deliberately posts, not a public URL.

## Rejected alternatives
- Backend renders a PNG/OG endpoint for the receipt → rejected: doubles the render path;
  the client canvas already ships for `/savings`, reuse the pattern.
- Alias `price_per_1m`/`provider` on the API → rejected: I map `{model,input_per_mtok,
  source}` on my side; keep the contract lean.
- Show `$0.00` when the server hasn't priced yet → rejected: violates the under-claim
  honesty rule (an invented number). Guarded off instead.
