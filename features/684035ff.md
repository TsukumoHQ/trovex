# P2a — Partitioned vec0 rebuild (task 684035ff)

## ROOT_CAUSE
The Active-Memory store grew past sqlite-vec's hard 4096 KNN ceiling. A single
flat `vec_docs`/`vec_chunks` shard meant boot/flagship KNN needed `k` up to the
whole-corpus size; once docs > 4096 the widen-retry issued a `k>4096` MATCH that
raised `OperationalError`, `/api/boot` 500'd, and the fleet lost recall at boot
(the P0 outage; the deployed clamp was a stopgap, not a fix).

## FIX (design LOCKED by cto = Option B: partition key = source_id)
Rebuild `vec_docs`/`vec_chunks` as vec0 **partitioned** tables keyed by
`source_id`, with `kind`/`lifecycle`/`status` as vec0 metadata columns for
in-KNN pre-filtering. Each source is its own bounded shard, so KNN always scans
a small partition with a tiny `k` — the 4096 ceiling is retired STRUCTURALLY
(clamp + widen-retry + `SQLITE_VEC_MAX_K`/`MAX_KNN_POOL` all removed).

- Default search (boot + flagship) scans the `trovex` (SSOT) partition; cold
  file-sources reached via explicit `source_ids` filter.
- `_migrate_partition_vec` rebuilds by REUSING existing embeddings (snapshot →
  drop flat → recreate partitioned → re-insert JOINing docs/chunks for
  metadata) — NO re-embed, offline, idempotent, runs after `_init_schema`.
- `kind` COALESCEd to `'doc'` at the write boundary (vec0 rejects NULL
  metadata); did NOT mutate `docs.kind`.

## AC deviation (noted for cto)
Partition key = **source_id** (not a literal `tier` column), per cto's locked
Option B. "ssot" = the `trovex` partition.

## Round 2 — reviewer finding + fix
FINDING (review-684035ff r1): `lifecycle NOT IN ('archived','pending_delete')`
is NOT pushed into the vec0 KNN, so it post-filters the k-window; on an
archived-heavy partition the k=50 nearest are all archived → filtered out →
silent recall squeeze (and P2a retired the widen-retry that used to compensate).

ROOT CAUSE (empirically proven): vec0 pushes `=`, `!=`, `IN` metadata
constraints INTO the KNN but NOT `NOT IN`. Test on a partition with 60 archived
docs (distance 0) + 10 live docs (farther), k=50:
  NOT IN → 0 live rows (squeeze)   |   != → 10   |   IN → 10.

FIX: replace the `NOT IN (a,b)` lifecycle exclude with chained `!=`
(`v.lifecycle != 'archived' AND v.lifecycle != 'pending_delete'`) in BOTH vec0
MATCH paths — `search.py::_vector_rows` and `store.py::search_chunks`. Each `!=`
is pushed into the KNN, so no post-filter squeeze; k stays tiny, structural win
intact. (`status != 'duplicate'` was already `!=` — unaffected.) The other
`NOT IN`s in the diff are plain-table SQL, not vec0 MATCH — untouched.

VALIDATION r2:
- New non-vacuous regression test
  `test_archived_heavy_partition_does_not_squeeze_live_recall` (60 archived at
  distance 0 + 1 live behind them): FAILS with NOT IN, PASSES with `!=`.
- Gate green: ruff clean, pytest 357 passed, brand clean.
- Live copy: tsukumo partition 3065 docs / 2666 duplicate / 0 archived — scoped
  KNN with the chained-`!=` exclude returns 50 live hits, no squeeze.
