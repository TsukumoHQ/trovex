## Ticket 9299f37d — cAST code chunking

ROOT_CAUSE: trovex's file-scan indexer only ever chunked code files with a paragraph-window, markdown-heading chunker (AST-blind) — it splits mid-symbol and mixes unrelated code into one chunk, which caps retrieval precision on code queries (bench baseline hit@1 = 0.25 on trovex's own corpus).

DECISION: port cAST (yilinjz/astchunk) greedy-merge/split over py-tree-sitter + tree-sitter-language-pack, scoped to retrieval only — repo-map-at-boot was re-scoped to NIWA (ticket 03219980) by founder decision 2026-08-21, out of trovex's scope. v1 languages: python/go/rust/typescript/tsx. Extracted the Merkle chunk-hash-reuse logic (previously living only in store.py's MCP-write path) into a shared, chunker-agnostic db.sync_doc_chunks(), and wired it into the indexer's file-scan path for CODE_EXTENSIONS — closing the gap where file-backed code docs got doc-level-only embedding.

Bench (real embedder, trovex's own corpus, 12 held-out grep-confirmed queries): baseline hit@1 3/12 (0.25) recall@5 10/12 (0.83) vs cAST hit@1 9/12 (0.75) recall@5 11/12 (0.92). Satisfies cto's bench-mandatory gate (message 81fd90a6).

REJECTED ALTERNATIVES:
- Full graph DB / LSP backbone for code understanding — out of scope per the original survey, not a retrieval-chunking concern.
- Retroactively chunking the existing markdown file corpus at chunk level in this same PR — deferred as a separate costed decision (scope containment); this PR only chunks CODE_EXTENSIONS, markdown file-backed docs stay doc-level.

[LEGACY_OPPORTUNITY]: store.py::_insert_chunks previously duplicated Merkle-hash chunk-sync logic inline (MCP-write-path only). Now delegates to the shared db.sync_doc_chunks — any future chunker (e.g. a markdown-chunker upgrade) can reuse the same sync path without re-deriving hash-reuse/cascade-prune semantics.

## Round-1 fix

ROOT_CAUSE: a deeply-nested AST (long chained expression, minified/generated code) recursed one Python call frame per AST level in `_merge_siblings` — uncaught `RecursionError` killed the entire `reindex()` for that file.

DECISION: rewrote `_merge_siblings` to walk with an explicit stack instead of call recursion — same external contract, no depth limit.

## Round-2 fix

ROOT_CAUSE: two REFUTED-by-execution findings. (1) Unlabeled code chunks (top-level statements, or anything nested inside an unnamed AST node) all shared `heading_path=[]` — `store.section_text`'s small-to-big join glues every chunk sharing a heading_path into one section, so a 396-token chunk in `db.py` expanded to 4106 tokens. (2) A single giant expression with no real symbol structure (generated/minified code) recurses into thousands of near-useless micro-chunks.

DECISION: tag any chunk with no symbol breadcrumb with a `line:column` label derived from its own byte span (column matters, not just line — minified code is one giant line, a line-only label collapses right back onto the same bug); labeled nodes keep sharing their breadcrumb on purpose (correct small-to-big reconstruction). Cap at 300 chunks/file with a flat-split fallback (same line:column labeling) past that.

REJECTED_ALTERNATIVE: catching RecursionError per-file instead of removing the recursion (round-1) — papers over the crash without fixing the actual depth-unsafe design, and doesn't help the fs-watch path which needs the same guarantee.
