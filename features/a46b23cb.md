## 2. Root cause & decisions

# P3-retention — importance ranking + TTL eviction (task a46b23cb)

ROOT_CAUSE: ranking was recency-only (freshness × status), so an old-but-critical
doc lost to recent trivia, and there was no automated way to age ephemeral,
low-value docs out of the corpus — it only ever grew.

## DELIVERED
- **Importance signal** (`retention.py`, schema). New `docs.importance` +
  `docs.pinned` columns (+ `lifecycle_changed_at` for time-in-state). `importance =
  status base + pin boost + saturating access frequency` (access from the
  `mcp_query_results` path hit counts). `recompute_importance` derives it
  deterministically; `SqliteStore.set_pinned` pins a doc.
- **Importance-blended ranking** (`search.py`). importance multiplies the FLAGSHIP
  hybrid score (`fusion × freshness × status × (1 + w_i·importance)`), so an
  old-but-important doc outranks fresh trivia. importance defaults to 0 on every
  row until a recompute runs → **no ranking change by default**.
- **TTL eviction sweep** (`SqliteStore.sweep_retention`). Deterministic +
  idempotent, measures time-IN-STATE via `lifecycle_changed_at`: OWNED low-value
  docs (stale/duplicate/superseded) age active→archived→pending_delete, then
  tombstone + hard-delete after a grace window. Recoverable (doc_tombstones).

## SAFETY DECISIONS (flag for review)
- **Ranking is MULTIPLICATIVE, not the AC's literal `w_r·recency + w_i·importance +
  w_rel·cosine`.** The hybrid path fuses vec+BM25 by RRF (not a raw cosine), and
  the boot floor depends on the dense path's ABSOLUTE score scale. A strict
  additive rewrite would break RRF fusion + the boot-floor invariant (both
  test-covered). Multiplying an importance BOOST into the existing hybrid score
  achieves "old-but-critical outranks trivia" while preserving every tuned
  invariant. The boot/dense path (`_make_result`) is left untouched.
- **Eviction is OPT-IN, default OFF** (`retention_sweep_enabled=False`), and
  hard-delete is DOUBLE-gated (`retention_hard_delete=False`). Default build =
  zero eviction behavior. This respects the goal ("down-rank, don't delete") +
  the destructive-op caution: pending_delete already hides a doc; actual deletion
  needs explicit opt-in and is tombstoned.
- **Exemptions**: owned records (kind='record') and pinned docs are NEVER evicted;
  only OWNED (source='trovex') docs are eligible (file docs are the indexer's);
  only low-value statuses archive (a live active canonical is never touched).
