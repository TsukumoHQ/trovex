## 2. Root cause & decisions

# P2c — write-policy split (task af03da67)

## GOAL
Stop fleet artifacts the store already owns from entering the KNN pool, and let
archival/reference docs be stored WITHOUT a vector — structurally bounding corpus
growth.

ROOT_CAUSE: unbounded corpus growth into the semantic pool — fleet per-agent
scratch .md (resume/checkpoint/lessons), already owned as capture records, were
re-indexed into vec_docs because the artifact ignore-globs were prefix-anchored
(`resume*.md`) and missed middle/suffix names (`trovex-backend-resume.md`); and
every written doc embedded unconditionally, with no lane for archival/reference
material that only needs BM25. Both feed KNN pressure the P2a partitioning bounds
per-source but doesn't prevent at the write boundary.

## CHANGES
1. **Widened artifact ignore-globs** (`config.py::default_ignore_globs`). The
   globs are fnmatch'd against the basename; the prior prefix form (`resume*.md`)
   matched only names STARTING with the token, missing the bulk of the fleet's
   files (`trovex-backend-resume.md`, `2026-checkpoint.md`). Now
   `*resume*.md` / `*checkpoint*.md` / `*lessons*.md` (+ `.niwa-decision.md`) —
   token anywhere in the basename. On the next reindex these on-disk copies stop
   entering `docs`/`vec_docs` (they're already owned as capture records).
2. **Store-only lane** (`store.py::put`). A new `Settings.store_only_kinds`
   (default `[]`, env `TROVEX_STORE_ONLY_KINDS`) gates embedding: a store-only
   kind is chunked + FTS-indexed (docs_fts + chunks_fts → full BM25) but gets NO
   `vec_docs`/`vec_chunks` row, so it adds ZERO KNN pressure. A store-only write
   is authoritative — it deletes any stale vectors if a doc flips into the lane —
   and skips dup-detection (no vector to compare).

## DECISIONS / notes
- `store_only_kinds` defaults EMPTY → opt-in + tunable (mirrors the fleet
  governance-enforcement decision: mechanism present, never imposed). The bloat
  reduction (DoD) is carried by the ignore-globs; the lane is the opt-in tool for
  archival material.
- BM25 completeness: store-only docs keep chunks_fts, so both doc- and
  chunk-level keyword search still find them; only the semantic pool excludes
  them (the JOIN on vec_docs/vec_chunks naturally omits them).
- Reindex implication: widening the globs means a reindex will DROP previously
  indexed artifact docs that now match — intended bloat shedding, not data loss
  (the owned capture records are the SSOT copies).
