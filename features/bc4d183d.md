## 2. Root cause & decisions

## review-trovex verdict: SHIP

ROOT_CAUSE: File-indexing pulled per-agent scratch (resume/checkpoint/lessons .md,
niwa decision blocks) into the store, and SSOT supersede leaves dead 'superseded'
forks — together the corpus crossed the sqlite-vec 4096 KNN ceiling (the P0
outage's underlying bloat). Exclusion was convention (.trovexignore), not enforced.

DECISION (three of the four acceptance criteria; the fourth flagged, see below):
1. Enforced-in-code ignores: Settings.default_ignore_globs (resume*/checkpoint*/
   lessons*.md, .niwa-decision.md) combined with each repo's .trovexignore at BOTH
   indexer scan sites. A repo without a .trovexignore still keeps scratch out, and
   the next reindex's existing cleanup DROPS any such file docs already indexed —
   the primary structural corpus reduction that keeps it under 4096.
2. Store.sweep_bloat(): deterministic + idempotent. Tombstone-DELETES superseded
   forks (removes their vec_docs rows so the KNN corpus actually shrinks — a
   lifecycle flag alone leaves the row counting toward `k`) and re-marks age-stale
   OWNED non-record docs (compute_status already ages file-backed docs on reindex;
   owned docs have no file, so the sweep owns their staleness; records never age).
3. Scheduled: wired into POST /reindex (runs on every reindex the deploy/fs-watch
   triggers) + `trovex sweep` CLI for cron. Idempotent, so repeated runs are safe.

DEFERRED (needs a concrete rule from cto — NOT silently dropped): the acceptance's
"collapse ephemeral owners (dev-60/61)" sub-item. The exact targeting is ambiguous
— which owner tags / numeric-suffix patterns count as ephemeral, and collapse-to-
what (delete? merge into a canonical owner record?). Owner records are already
upsert-by-stable-ext_id (no dup pile per owner), so "collapse" implies a
cross-owner rule I won't guess. Flagged for a one-line rule, then a fast follow-up.

REJECTED ALTERNATIVE: tombstoning superseded via lifecycle='pending_delete' only.
That keeps the vec_docs row, so the KNN corpus would NOT shrink — defeats the
"drops back well under 4096" goal. Hard delete (with a recoverable tombstone
snapshot) is required to remove the vec row.

VERIFICATION: tests — the sweep tombstones a superseded fork (recoverable via
list_tombstones, no orphan vec rows), ages an owned canonical, never ages a
record, and is a no-op on the second run (idempotent); a reindex excludes the
built-in agent-artifact globs and never re-adds them on re-index. Full gate green:
ruff check src tests, pytest -q -> 355 passed, brand guard clean. Rebased onto
origin/main after the update-guard (54109b2) merged.
