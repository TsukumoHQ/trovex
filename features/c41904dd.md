## 2. Root cause & decisions

## review-trovex verdict: SHIP

ROOT_CAUSE: Duplicate docs (status='duplicate' — a near-copy of a canonical doc,
~56% of the corpus) were only DOWN-WEIGHTED (STATUS_WEIGHT 0.6), so they stayed
in the KNN/BM25 candidate pool and diluted top-K and the rerank pool. On a
dup-heavy store they crowd canonical hits out of the pool BEFORE scoring, so a
mere weight can't recover them.

DECISION: Exclude status='duplicate' from the DEFAULT candidate pool (same shape
as the lifecycle filter), opt-in via a new include_duplicates flag on search():
- search.py _vector_rows: SQL gains `AND d.status != 'duplicate'` unless opted in.
- search.py _passes_filters (BM25-only path): guard drops duplicates unless opted
  in — keeps the two candidate sources consistent.
- search() threads include_duplicates (default False). canonical/plan/stale
  unaffected; the rerank now scores a clean pool.
No wire change: /api/search and the MCP search inherit the default-exclude; there
is no user-facing knob to add for the outage-clearing goal.

TEST + FALLOUT: new test asserts a write-path-flagged duplicate is absent by
default and present with include_duplicates=True. Three pre-existing
test_hybrid_retrieval tests broke and were fixed FAITHFULLY, not weakened:
- Two use ConstEmbedder (every doc → the SAME vector), which makes the write-path
  dedup flag all-but-one CORPUS doc as a duplicate — a hermetic-harness artifact,
  not real behaviour. Raised dup_cosine_threshold >1.0 in those two so the whole
  corpus stays in-pool; that is exactly what a real (distinct-embedding) corpus
  does. The BagEmbedder no-regression test needed no change (distinct vectors).
- test_freshness_status_weighting_preserved asserted a 'duplicate' stays in-pool
  but down-weighted — the very behaviour this task removes. Repointed it to
  'stale' (still in-pool, weight 0.5) so it still guards the status-WEIGHT
  invariant, and added an assertion that both docs stay in the pool.
