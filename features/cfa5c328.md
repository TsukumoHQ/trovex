## 2. Root cause & decisions

# feat/savings-benchmark — $-priced savings ledger + reproducible benchmark

Task cfa5c328 — turn trovex's "measured token savings" moat from a claim into
reproducible, shareable, $-priced proof. Steal #1 from competitive study
37fa8519 (Code Context Engine's `cce savings` credibility hook).

ROOT_CAUSE: trovex's whole moat is measured token savings, but pre-this-change
the number was TOKENS-only and had no reproducible, pinned proof behind the
headline "~60%". Two gaps: (1) no $ dimension — a token count doesn't land with
a buyer the way a dollar figure does; (2) the benchmark defaulted to "this repo",
which drifts commit-to-commit, so the published % was not reproducible by an
outsider. Result: the moat was asserted, not provable.

## Decision

Additive, offline, key-free. No schema change (rides the existing append-only
`mcp_queries` ledger + `retrieval_eval_runs` precision gate).

- **pricing.py** — new module. Prices saved tokens (which are INPUT tokens: the
  context an agent would have re-read but didn't) at a stated mid-market input
  rate (`gpt-5.4`, $2.50/1M, matching insights.py). Env-overridable
  (`TROVEX_PRICE_MODEL`, `TROVEX_PRICE_PER_MTOK`); bad/negative override degrades
  to the default, never raises. Every $ ships a `{model,input_per_mtok,source}`
  block so it is never context-free.
- **savings.py** — additive `saved_usd` + `saved_usd_at_precision` + `pricing`
  on totals/session/per-agent/per-session + the markdown receipts. Honesty rail
  preserved: `saved_usd_at_precision` is null when routing precision is
  unmeasured — the $ is never inflated above the raw floor.
- **cli.py** — `trovex savings`: cumulative $-priced dashboard (tokens + $ +
  per-agent), gated on measured hit@1, honest caveat otherwise.
- **benchmark** — pinned, self-contained corpus (8 neutral fictional "Acme Notes
  API" docs) + fixed query set. `run.py --fixed` is deterministic (identical
  token numbers on re-run; only `ran_at` metadata differs) and writes the
  committed `src/trovex/_benchmark.json` (shipped in the wheel via pyproject
  artifacts). Current result: ~60% pooled (median 59%). METHODOLOGY.md documents
  the model + the under-claim honesty rails.
- **server.py** — `GET /api/savings/benchmark` serves the committed proof.

## Rejected alternatives

- **New /api/savings/ledger endpoint** for the $ figures — rejected. The $ is a
  property OF the existing savings rows, not a new resource; additive fields on
  the existing shapes = smallest frontend delta (confirmed w/ trovex-frontend).
- **Benchmark against a pinned git ref of this repo's docs/** — rejected. A user
  on a later commit gets different docs → not reproducible. A vendored,
  version-controlled corpus is the honest fixed baseline.
- **A separate `_benchmark.json` copy under benchmarks/** served by the API —
  rejected. Two copies drift; the single committed copy lives inside the package
  so it both ships in the wheel and is the one source the API reads.
- **Backend-rendered PNG/OG receipt endpoint** — rejected/split. trovex-frontend
  owns the shareable React receipt + client-side PNG; backend exposes numbers
  only (confirmed via relay, so we don't double-build).
