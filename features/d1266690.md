## 2. Root cause & decisions

# feat/doc-lifecycle — reversible curation lifecycle (active/archived/pending_delete)

Task d1266690 — trovex steal #5 from study 37fa8519 (The Vault).

ROOT_CAUSE: SSOT curation had only two blunt options — a near-dup CREATE is
HARD-BLOCKED (needs force=true), and removal is a hard delete. There was no
reversible "hide this superseded doc from retrieval without destroying it" path,
so cleaning up the one-topic-N-near-copies bloat meant either friction (block) or
irreversible loss (delete). `status` (canonical/plan/stale/duplicate) only
*weights* ranking; nothing FILTERED a doc out of retrieval.

## Decision (additive, no retrieval regression)

New curation axis `docs.lifecycle` (default 'active'), DISTINCT from `status`:
lifecycle FILTERS visibility, status weights ranking.

- Schema: `docs.lifecycle TEXT NOT NULL DEFAULT 'active'` + idx + idempotent
  `_migrate_add_lifecycle` (every pre-migration doc defaults active → nothing
  disappears).
- `store.set_lifecycle(ext_id, state)` — reversible, validates the enum
  (active/archived/pending_delete/stale), ValueError on a typo (fails loud).
- Retrieval defaults to the active canon: both `search_chunks` (chunk path) and
  `Searcher.search` (doc-router) hide 'archived' (unless include_archived=True)
  and ALWAYS hide 'pending_delete' (a grace window before real removal).
- MCP: `trovex_archive(doc_id, restore=False)` — write-gated, reversible hide/
  restore, the soft alternative to trovex_delete. `trovex_search` gains
  `include_archived`. Contract + resources tests updated for both.

## Rejected alternatives

- **Overload `status`** with archived/pending_delete — rejected. status drives
  ranking weights + markers (★◯✗⚠); mixing a visibility axis into it would
  couple curation state to relevance scoring. A separate column is clean.
- **Auto-archive the near-dup on block** — deferred. This ships the reversible
  mechanism (archive/restore + filter); wiring it into the write-time dedup
  decision is a follow-up (keeps this PR's blast radius small + the default
  behavior identical for existing callers).
- **Rewire trovex_delete through pending_delete** — rejected. Delete already has
  a tombstone/undelete recovery path (task 9de87036); pending_delete is an
  independent grace state that retrieval hides, not a replacement for that flow.
