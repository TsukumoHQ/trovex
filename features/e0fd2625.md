## 2. Root cause & decisions

## review-trovex verdict: SHIP

ROOT_CAUSE: "One canonical doc per topic" was only an advisory soft-flag, so the
live store had TWO canonical same-title docs. Nothing at the schema level stopped
a second live canonical from being forked.

DECISION: Make SSOT a DB-enforced invariant.
- Schema: docs.canonical_topic (slug of title) + partial UNIQUE INDEX
  (workspace_id, canonical_topic) WHERE status='canonical' AND canonical_topic IS
  NOT NULL. canonical_topic is set ONLY for trovex-owned (source_id='trovex')
  NON-ephemeral docs; file-backed + ephemeral docs stay NULL, and NULLs don't
  collide in a unique index — so two repos' READMEs never clash and ephemeral
  snapshots are exempt.
  NOTE on the index predicate: I used `canonical_topic IS NOT NULL` rather than the
  acceptance's literal `kind NOT IN (ephemeral)`. In SQLite `NULL NOT IN (...)` is
  NULL (not true), so the literal form would DROP normal kind-less trovex docs out
  of the constraint — a correctness bug. IS NOT NULL captures exactly the intended
  set (non-ephemeral trovex docs carry a topic; everything else is NULL).
- Migration _migrate_add_canonical_topic (additive, idempotent, runs AFTER the
  lifecycle migration): ADD COLUMN, backfill the slug for trovex-owned
  non-ephemeral docs, DE-DUPE existing same-title canonical pairs (keep newest by
  mtime, supersede the rest) BEFORE building the index so the build can't fail on a
  pre-existing collision. Uses only ADD COLUMN + CREATE INDEX (portable; the live
  box's sqlite needs no DROP COLUMN — that's test-only).
- Write path: store.put(force). A CREATE that would fork a second live canonical
  raises TopicCollisionError; force=True atomically SUPERSEDES the prior canon
  (status='superseded' + lifecycle='archived') in the SAME transaction. Reusing
  lifecycle='archived' hides the superseded doc via the EXISTING retrieval
  mechanism — no new search filter. mcp_app threads force and translates the
  collision into a block-and-point pointer.
- 'superseded' added to STATUS_WEIGHT (0.3) / STATUS_MARKER (⤺).

INTERACTION FIXED: the batch-dedup test (from the just-merged aa08ffaa) created two
same-title 'reference' docs — now a TopicCollision under SSOT. Updated it to use

REJECTED ALTERNATIVE: a real new 'superseded' retrieval filter in search.py. Not
