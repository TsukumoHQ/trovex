## 2. Root cause & decisions

# feat/access-ladder — graduated-access ladder (card → passage → full)

Task f18071f1 — trovex steal #3 from study SSOT 37fa8519 (SDL-MCP narrative).

ROOT_CAUSE: trovex retrieval was flat — a query returned the best passage (or
the whole doc with full=true), with no cheaper rung. An agent could not ask for
"just enough to decide" before paying for a full passage/doc. The moat is
measured token savings; a deliberate escalation ladder makes token-discipline an
explicit, named contract instead of an implicit default.

## Decision

Additive, non-breaking. New optional `tier` param on `trovex_read`:

    tier="card"     → tier 1: heading breadcrumb + ~50-word extract (cheapest, 76 tok in bench)
    tier="passage"  → tier 2: the matched section (DEFAULT — unchanged)
    tier="full"     → tier 3: the whole doc

- Default (no tier, no full) STAYS passage → existing callers unaffected.
- `full=true` kept as a back-compat alias for tier="full".
- Invalid tier → typed `unknown_tier` validation error (never silent).
- Card branch is strictly cheaper than passage: it does NOT small-to-big expand;
  it extracts ~50 words of the matched chunk + a breadcrumb + an escalation hint
  pointing at the next rungs. Reuses the savings ledger (_log_retrieval).

Contract test (test_mcp_contract) updated to add `tier` to trovex_read's frozen
prop set, with a comment noting it's an additive optional wire change.

## Rejected alternatives

- **Separate `trovex_card` tool** — rejected. Splitting the ladder across tools
  fragments the contract; one tool with a `tier` rung keeps the escalation
  legible and the wire surface small.
- **Apply tier to the doc_id (exact-read) path** — rejected/out-of-scope. An
  exact doc_id read is already precise; the ladder is about *query* retrieval.
  Documented that tier is ignored with doc_id.
